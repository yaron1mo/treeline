# Change log

Newest on top. Format: `YYYY-MM-DD — [agent] area — what changed and why`. Do not edit old entries.

- 2026-11-05 — [claude] data — Renamed `machine_gun` to "Machine gunner" (Yaroslav's choice for the first playable). Said the drone pilot with two upgrade branches is wanted; waiting for the branch names before adding rows.
- 2026-11-05 — [claude] data — Defenders added to the units table (side = defence): rifle squad, machine gunner, sniper, mortar crew, anti-tank missile team, air defence gun, observation post. New columns `weapon_class` (matches the attackers' `targetable_by`) and `build_cost` (budget points, defenders only). Every number is a Claude proposal to balance; base sight 30 m (sniper 40, observation post 50). Why (Yaroslav): defenders were the missing half of the table. Which two are the first playable ones is still open.
- 2026-11-05 — [claude] sim — Fix (Yaroslav's screenshot): shadows behind small obstacles showed as thin broken curved lines. Cause: the sight ray was sampled every 1 m and skipped cells it only clipped. `VisionMap.SeeChance` now walks every cell the ray touches (grid traversal) with exact entry and exit distances, so shadow wedges are solid and the belt blur uses exact distances. 14 tests pass under Mono; not yet run in Unity.
- 2026-11-05 — [claude] sim — Fix (Yaroslav): a unit standing inside a forest belt or grove saw almost nothing. Now soft obstacles blur only along the ray: targets inside the belt, or behind a belt the ray entered from outside, get a recognition chance that falls with distance; past the edge of the belt the observer stands in the view is clear. So the circle in a horizontal belt is an hourglass: short along the belt, full towards the open ground. New EditMode test for it (14 tests pass under Mono; not yet run in Unity).
- 2026-11-05 — [claude] sim — Vision v1 in `Treeline.Sim`: `Csv` reader, `ObstacleTable` (reads `obstacles.csv`: sight, cover per shooter class, hill bonuses, move costs), `VisionMap` (obstacles rasterised to the 2 m grid; `SeeChance` for one point, `Compute` for a whole circle). Full obstacles hide everything in their shadow sector but not their own body; soft ones (grove, forest belt) give a recognition chance that falls with distance behind them; standing on a hill raises the radius and does not block. Debug view: new test field `vision-test.json`, buttons Vision on/off and Left/Right/Up/Down move an observer (30 m base sight) and show seen / hidden cells. 9 new EditMode tests in `VisionTests.cs`. Checked outside Unity with a Mono C# compiler (all 13 tests, old and new, pass); not yet run in Unity. Not done: shared vision between units, reading `sight_range_m` from `units.csv`, NavGrid still uses its own move costs, cover multipliers are parsed but not used in combat.
- 2026-11-05 — [claude] data — Replaced the `cover` and `vision` tabs and CSVs with one `obstacles` tab / `unity/Assets/Data/obstacles.csv`: sight (full / soft / none), cover per shooter class, hill bonuses when standing on it, and the terrain move costs from `NavGrid.cs`. Why (Yaroslav): obstacles are not destructible, a bush hides but does not protect, rocks and wrecks protect both sides, a hill gives bonuses on top and acts like a rock behind. Old cover values kept for trees and trench. Obstacle numbers are proposals. Code still uses its own move costs until the loader is written; `cover.csv` was not read by any code.
- 2026-11-05 — [claude] data — Vision rules from Yaroslav: base sight 30 m, rising with unit level; `block` obstacles (rock, wreck, heap) hide everything in their shadow sector, `soft` ones (bush, grove, forest belt) blur it with a recognition chance that falls with distance; attackers share vision. Added `vision` tab and `unity/Assets/Data/vision.csv` (obstacle values are proposals), filled `sight_range_m` in `units.csv` (recruit 25, regular 30, special forces 40, vehicles 30, recon UAV 40; special forces and recruit values are proposals). Code for the visibility sectors is not written yet.
